# 项目 Agent 规则

## 沟通

- 默认使用中文，必要的代码、命令、API、类型名和固定术语保留原文。
- 先给结果和证据，再补充必要说明；简单任务保持简洁。

## 开始工作

- 先读取当前目录及上级生效的项目规则、README 和任务相关文档。
- 修改前确认 Git 根目录、当前分支和 `git status --short`。
- 识别用户已有未提交修改；不得回滚、覆盖或混入当前任务。
- 先查源码、测试、配置和日志，能自行确认的信息不要抛回用户。

## 修改边界

- 只修改完成当前目标所需的最小范围，不顺手重构无关代码。
- 遵循项目现有结构、命名、依赖、错误处理和生成流程。
- 修改真源，不直接手改生成物；需要更新生成物时运行项目生成命令。
- 遇到重叠修改时先读 diff，选择能够保留用户工作的实现方式。

## 调试与验证

- Bug 修复先复现问题或建立可信证据，再修改根因。
- 同类失败连续两次后停止微调，重新检查错误原文和前置假设。
- 修改后运行与风险匹配的测试、构建、静态检查或真实运行验证。
- UI 变化检查真实渲染和交互；无法检查时明确视觉验证缺口。
- 对可能挂起的测试、构建、浏览器和外部工具设置时间边界。
- 超时后停止重复等待，保留证据，检查残留进程并使用替代验证。
- 没有实际验证证据时，不声称“完成”“修复”或“通过”。

## Git 安全

- 不使用 `git reset --hard`、强制推送或覆盖式 checkout，除非用户明确要求并确认风险。
- 不使用 `git add .`；只暂存当前任务涉及的路径。
- 提交前检查 staged diff、文件列表和仓库边界。
- 不提交密钥、临时夹具、缓存、构建输出或无关用户修改。

## 必须暂停的情况

继续执行需要以下新增授权或信息时，先完成安全的只读检查，再提出具体问题：

- 账号、密钥、凭据或用户独有的业务判断；
- 永久删除、数据迁移、大范围覆盖或难以恢复的操作；
- 生产环境、真实用户、费用、权限或合规影响；
- 对外发布、发送消息、创建 PR 或超出已授权范围的推送；
- 会显著改变公共 API、兼容性、数据模型或产品结果的取舍。

## 交付

交付时说明：

1. 已实现或已确认的结果；
2. 实际运行的验证及结果；
3. 仍然影响目标的风险；
4. 仅在需要时给出用户下一步。
